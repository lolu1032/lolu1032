### 박성호

AI로 만드는 사람은 많아졌습니다. 저는 **AI가 낸 결과를 믿지 않는 장치**를 만듭니다.

모델의 답은 그럴듯할수록 검증이 어렵고, 같은 모델에게 다시 물으면 같은 방향으로 틀립니다.
그래서 확률적인 출력을 결정적인 것으로 바꿔놓는 쪽을 만들어 왔습니다.
무엇을 맡기고 어디서 끊을지, 통과 판정을 누가 내릴지를 정하는 일입니다.

---

#### 검증을 어디에 두었나

**[pantheon-skills](https://github.com/lolu1032/pantheon-skills)** — 검증을 다른 모델의 공격에

같은 과제를 여러 갈래로 구현하고, 각 결과를 다른 모델이 공격하게 한 뒤 견딘 것만 남깁니다.
사람이 읽고 지나쳤던 순환 루프 오분류 결함이 이 구조에서 잡혔습니다. MIT.

**[daedalus](https://github.com/lolu1032/daedalus)** — 검증을 실측에

LLM 은 그럴듯한 스키마를 그려주지만 그 설계가 나중에 무엇으로 터지는지는 말해주지 않습니다.
오픈소스 스키마 969개에서 패턴 31종을 뽑고 PostgreSQL 실험 42개를 7회씩 반복해 1,011회를 측정했습니다.
실행 시간이 회차마다 10~19% 흔들려서, 매번 같은 값이 나오는 읽은 블록 수를 근거로 삼았습니다.
카운터 인덱스가 HOT 업데이트를 죽이는 것, 자식 FK 인덱스 누락으로 부모 삭제가 75배 느려지는 것을
수치로 검출합니다. MIT.

**[taperun](https://github.com/lolu1032/taperun)** — 판정을 LLM 에서 빼기

기능 하나를 실제 크롬에서 끝까지 돌려 영상으로 남깁니다.
통과 판정은 LLM 이 아니라 시나리오의 expect 단계가 냅니다.

**[Gotcha](https://github.com/lolu1032/Gotcha)** — 에이전트가 놓친 것을 잡는 테스트 라우터

#### 회사에서는

같은 원칙을 제품에 적용해 왔습니다.

- **광고 배너 생성** — 한 글자 오타가 위법인 업종이라 법정 표기는 모델에 맡기지 않고 코드가 덧입히게 했습니다
- **AI 영상 생성** — 생성 호출이 곧 과금이라 대사와 동작으로 지문을 만들어 같은 컷이면 부르지 않게 했습니다. 원가는 문서가 아니라 코드에서 산출해 실제 29편과 4원 차이로 맞췄습니다
- **통합 CMS** — 데이터 모델 18종을 설계해 관리자 화면 60개, REST API 118개까지. 업종 중립 코어와 플러그인으로 갈라 두 번째 업종을 코어 수정 없이 붙였습니다
- **서버 운영** — VPS 5대와 자체 메일 서버(SMTP/IMAP, SPF/DKIM/DMARC). 장애는 추측하지 않고 대조군을 만들어 갑니다
